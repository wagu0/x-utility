# X Utility

X（旧Twitter）で、マウスを重ねたポストへの操作や画像の保存を、自分で設定したショートカットキーで行うChrome拡張機能です。

[Chrome Web Storeでインストール](https://chromewebstore.google.com/detail/x-utility/gnlnlahoefpdkllpohjnfdfmodicmkee?hl=ja)

## 開発背景

普段Xを使う中で、頻繁に行う操作を楽にするために開発しました。以前から個人利用していた画像保存機能を作り直し、2026年5月末頃からこのリポジトリで開発しています。

自分で使うための個人開発で、学習やポートフォリオとしての公開も目的としています。今後もショートカットに限らず、Xを便利に使う機能を追加していく予定です。この方針から「X Utility」と名付けました。

## 主な機能

| 機能 | 動作 |
| --- | --- |
| Save image | マウスを重ねた画像を1枚保存する |
| Like | マウスを重ねたポストのいいね・解除を行う |
| Bookmark | マウスを重ねたポストのブックマーク・解除を行う |
| Repost | マウスを重ねたポストのリポスト・解除の選択メニューを開く |
| Open Chat | Xのナビゲーションからチャットを開く |
| Open Profile | Xのナビゲーションから自分のプロフィールを開く |

各機能に単独のキーを割り当てられます。設定画面ではキーの登録・解除、重複チェック、Escによる登録キャンセルに対応しています。

リポストの確定は、開いたメニューで行います。

## 使い方

1. Chrome Web Storeからインストールし、拡張機能のアイコンから設定画面を開きます。
2. **Record shortcut** をクリックしてキーを登録します。初期状態では未設定です。
3. `https://x.com/` を開き、対象の画像やポストにマウスを重ねて、設定したキーを押します。インストール前から開いているページは再読み込みしてください。

チャットとプロフィールを開く操作では、ポストにマウスを重ねる必要はありません。

画像の保存先には、ブラウザのダウンロード先にある `X_Images` フォルダを指定します。ファイル名は投稿の日付やユーザーIDなどから生成します。

## 技術・構成

JavaScript・HTML・CSSと、Chrome拡張機能のManifest V3を使用しています。外部ライブラリやビルドツールは使用していません。

| ファイル | 役割 |
| --- | --- |
| [manifest.json](manifest.json) | 対象URL・権限・実行ファイルの宣言 |
| [content.js](content.js) | X上でのキー入力、ホバー対象の取得、DOM操作 |
| [service_worker.js](service_worker.js) | 画像のダウンロード要求、設定画面の起動 |
| [options.html](options.html) / [options.js](options.js) / [options.css](options.css) | ショートカット設定画面と設定の保存 |

設定は `chrome.storage.local` に保存し、`chrome.storage.onChanged` で変更をXページに反映します。宣言している権限は、設定保存用の `storage` と画像保存用の `downloads` です。

## 実装で意識した点

### DOMへの依存をまとめる

XのDOMが変わった際に修正箇所を見つけやすくするため、ポストや操作ボタンの主要セレクターを定数にまとめています。ホバー対象は、ページ全体で受け取る `mouseover` イベントと `closest` で取得します。

### 機能ごとの処理と共通処理を分ける

不具合の影響範囲を小さくするため、各操作を関数に分けています。ページ内の `keydown` イベントから、キーとアクション、アクションと関数を対応付けた `Map` を使って処理を呼び出します。入力中・修飾キーの同時押し・長押しによる連続実行を防ぐ判定は、共通処理にまとめています。

設定画面も `data-action` と共通クラスを使って各項目を扱い、キー登録や解除の処理を共通化しています。

### 失敗時の処理を用意する

対象の要素や画像URLが取得できない場合は処理を中断し、状況に応じてログを出力します。通信・ダウンロード要求のエラーも確認し、Service Workerからの応答に応じて通知を表示します。

### 画像保存を実行場所ごとに分ける

Content Scriptで画像URLや投稿情報を取得し、`chrome.runtime.sendMessage` でService Workerに渡します。Service Workerは `chrome.downloads.download` を呼び出し、要求の結果を非同期で返します。

### 苦労した点

開発では、特に操作対象の判定、画像保存処理、ショートカット設定、Content ScriptとService Worker間の連携に苦労しました。

X上で操作対象を取得する際、いいねやブックマークなどはポスト単位で処理する一方、画像保存ではポスト内のどの画像を選択しているかまで判定する必要があります。そのため、ポストと画像をそれぞれ取得・保持し、機能に応じて使い分ける設計にしました。

画像保存では、X上に表示されている画像から元解像度の画像を取得するため、画像URLのクエリパラメータを変更し、実際に元の解像度で取得できているかを複数の画像で確認しながら実装しました。また、投稿日時・ユーザーID・画像の枚数や位置など、複数の要素から必要な情報を取得し、保存時のファイル名を生成する処理にも苦労しました。

ショートカット設定では、設定画面を作成するだけでなく、キー入力の記録、重複チェック、Escによるキャンセル、設定の解除、`chrome.storage.local`への保存、現在の設定の画面への反映など、細かな仕様を一つずつ実装する必要がありました。特に、どの項目がキー入力を待っている状態なのかを管理しながら、保存されている設定と画面表示を連動させる部分に苦労しました。

画像のダウンロードでは、Content Scriptで取得した画像URLとファイル名をService Workerへ渡し、`chrome.downloads` APIで保存する構成にしました。実装時は、Content ScriptとService Worker間でのデータの受け渡しや非同期の応答処理に加え、それぞれ確認するConsoleが異なるため、処理がどこまで実行されているかを切り分けながらデバッグする点にも苦労しました。

## ローカルでの実行

1. このリポジトリをダウンロードまたはクローンします。
2. Chromeで `chrome://extensions/` を開き、デベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から、`manifest.json` があるフォルダを選択します。

読み込み後は、上記の「使い方」に沿ってキーを設定します。

## 動作確認・制約

Windows 11のChrome・Braveで、実装時の操作・ログと日常利用を通じて動作確認しています。網羅的な検証や自動テストは行っていません。

- プロフィールのメディア画面全体では、DOM構造が異なるため画像保存が機能しません。
- XのDOM構造や属性の変更によって、各操作が動かなくなる可能性があります。
- X標準ショートカットとの競合や動作への影響は未検証です。同じキーを割り当てる場合は注意してください。
